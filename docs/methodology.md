# 分析口径与方法说明

本文件说明 `analysis/` 如何把投诉类别、证据完整度、关联反馈、当前处理
阶段、历史到达变化与团队可用容量组合成可重跑的积压压力与排班分析。
所有估计都是**供人员核查的区间**，不替代主管与核查人员的判断。

## 1. 运行方式

```bash
# 分析（更新 data/ 后原样重跑即可，输出覆盖 outputs/）
python3 -I run_analysis.py --data-dir data --output-dir outputs

# 测试（无第三方依赖，Python 3.11+）
python3 -I run_tests.py
# 或沿用原有方式
python3 -m unittest discover -s tests
```

`-I`（隔离模式）保证脚本目录与环境变量中的同名模块不会干扰标准库
导入；数据路径始终由参数显式传入。

## 2. 数据关系与角色

| 文件 | 角色 | 关键口径 |
|---|---|---|
| `complaints.csv` | 个案台账 | 空字段=资料未提供，不是零或业务否定 |
| `events.csv` | 多期状态时间线 | 按事件日期排序重建阶段；未登记事件类型不报错，转质量标记 |
| `evidence.csv` | 证据记录 | `supersedes` 指向的旧证据视为被取代 |
| `links.csv` | 个案关联 | 仅 confirmed 的 same_household 自动并簇；未复核关联进复核队列 |
| `arrivals.csv` | 各期到达 | 收到件数、独立家庭数、更正/撤销量分列 |
| `capacity.csv` | 各期排班 | `available_people` 是已安排人数，不是人均处理件数 |

## 3. 当前队列与等待归属（`case_states.csv`）

每个个案按事件时间线重建为一个当前阶段，并区分等待归属：

- **internal（等内部判断/排期）**：`new`、`assigned`、`received_evidence`、
  `transferred` 等，占用团队产能；
- **external（等消费者补件）**：最后一个事件是 `waiting_consumer` 且尚未
  收到补件，不占当期产能；
- **resolved（已终结）**：`closed`/`withdrawn`/`merged`，统计在终结事件
  截止，之后不再累计等待。

等待时长拆成两类，不混算：

- 内部处理天数：`assigned → waiting_consumer`、`received_evidence → ...`
  等团队在办区间；
- 外部等待天数：`waiting_consumer → received_evidence` 的补件区间。

未结案个案的未结束区间是**右截断**样本：计入“开放区间天数”，但在产能
估计中用放大系数处理，不当作完整办案时长。没有任何事件的个案（如
C-3）保持 `new` 且归属内部，并打 `no_events` 缺口标记——没人接手不
等于在等消费者。

## 4. 证据完整度（`evidence_summary.csv`）

被取代的证据不参与判断；综合状态分四档：

1. `complete`：存在有效且完整的证据；
2. `partial`：只有部分证据；
3. `unknown`：收到证据但完整度未知；
4. `missing`：无任何证据记录。

unknown/missing 是“资料不足”，在优先级里走保守下限（默认 0.5），
**绝不会因为缺资料而判为低风险**。

## 5. 关联反馈与去重（`household_clusters.csv`、`link_review_queue.csv`）

- 并查集同时依据 `household_ref` 与 confirmed 的 same_household 关联
  合并成家庭簇；
- `similar_phrase` 与所有 unreviewed 关联**不自动并案**，进入复核队列，
  避免把同一问题的重复反馈错误放大或合并；
- 影响范围以“簇内未结个案数 / 独立家庭数”表达。重复反馈能说明影响面，
  但独立家庭与未解决案件均按去重后计数，不会重复计算。

## 6. 到达变化与预测（`arrival_forecast.csv`）

对每个类别用历史各期做最小二乘线性趋势外推（样本不足或斜率接近零时
退化为历史均值），并以历史残差标准差给出低/高档区间，再用历史最小/
最大值夹取，保证区间非负且不脱离已观察范围。独立家庭按历史占比同步
外推；`correction_count` 只作背景事实，不并入新需求。

台账中存在但到达汇总缺失的类别（本样本为 renewal）：预测退化为仅
依据投诉台账提交数的弱兜底，`basis=no_history` 并打
`arrival_category_missing` 缺口标记，主管可一眼识别其可信度低于
正式到达汇总。

## 7. 历史办案过程与产能（`throughput_estimate.csv`）

排班人数不是产能。估计链条为：

1. 从时间线提取各团队的内部区间（外部等待剔除）；
2. 已结案个案得到完整办案天数；未结案只有截断区间时，高端天数按
   `censored_high_multiplier`（默认 1.5）放大，并保留不确定性地板；
3. 人均周产能 = 每周工作日 × 利用率 ÷ 单件办案天数，利用率取
   0.70 / 0.85 / 0.95 三档；
4. 样本不足 3 个、仅有截断样本、完全无观察均写入备注与质量标记。

团队在排班表中缺失（本样本 T-3 有处置事件但无排班）时，产能无法
量化：投影中该团队的估计产能留空、处理量为 0、打
`team_missing_from_capacity_schedule`，而不是假设为零人力或零需求。
专长标签与实际处置类别不一致（T-2 标注 advice 却处置 renewal）同样
出警告，提示核对路由。

## 8. 优先级（`priority_ranking.csv`）

未结个案按五个 0–1 因子加权（权重集中在 `analysis/config.py`）：

| 因子 | 含义 | 缺失处理 |
|---|---|---|
| age | 内部等待年龄（总年龄兜底） | 无提交时间则打标记 |
| impact | 影响带 high/medium/low | unknown 取保守 0.6 |
| readiness | 证据就绪度 | unknown/missing 取保守下限 0.5 |
| scope | 家庭簇影响范围 | 按独立家庭数，封顶 1.0 |
| stage | 当前阶段可推进度 | 外部等待显著低于内部可推进 |

输出包含总分、分档（high/medium/low）、每个因子的取值与一句可核查
的 `rationale`，以及 `caution_flags`。排序确定且可复现。

## 9. 多周期积压投影（`backlog_projection.csv`）

对每个“类别 → 负责团队”，在未来 N 个 ISO 周周期（默认 4）上按三种
情景滚动模拟：

| 情景 | 到达 | 补件回流 | 人均产能 |
|---|---|---|---|
| pessimistic | 高档 | 提前（lag 减一个波动） | 低档 |
| central | 中档 | 历史均值 | 中档 |
| optimistic | 低档 | 滞后 | 高档 |

每期恒等式：`期初内部积压 + 新增到达 + 外部回流 = 内部需求`，
`期末积压 = 内部需求 − 估计处理量`，处理量不超过需求；外部等待个案
按历史补件时长估计回流周期，回流前只减少“期末外部等待”数，不占
产能。未来周期没有新排班行时，沿用最近一期已排人数并打
`capacity_extrapolated_from_<period>` 标记。

## 10. 人员建议与可追溯性（`staffing_recommendation.csv`、`recommendation_audit.json`）

建议人数 = 跟上来量所需人数（平均周需求 ÷ 情景人均产能）
+ 清积压加人（当前内部积压 ÷ 约定清积压周期 ÷ 人均产能），
并与最近一期已排人数比较得到缺口。无法量化产能或无排班时缺口留空，
只给事实与标记，不编造数字。

每条建议在审计 JSON 中都能追到触发事实链：历史到达各期数值与预测
依据、当前积压（含具体个案编号与去重家庭数）、办案区间观察与产能
三档、相关团队的完整排班行、外部补件时长假设以及情景参数。

## 11. 已知限制

- 样本只有 4 个到达周期且无结案的 T-1/T-2 团队，趋势与产能估计的
  不确定性较大，已通过区间、截断放大和质量标记显式表达；
- 合并/拆分/撤回事件已在时间线类型中登记，终结类事件会停止等待
  累计，但本合成样本未包含拆分后的新个案编号链，未来数据出现时
  无需改口径即可处理；
- 所有参数（周期数、利用率、权重、清积压周期等）集中在
  `analysis/config.py`，调整后重跑即得到口径一致的新结果。
